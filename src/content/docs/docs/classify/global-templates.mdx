The **Classification Templates** screen (under **Apps → Classification
Templates**) is where a Confluence administrator defines classification **once
for the whole site** and rolls it out to many spaces consistently. This is the
recommended way to keep every space using the same classification levels,
colours, labels, and restrictions.

## What a global template is

A global template is a named, reusable set of **classification levels** — the
same levels described in
[Space Settings](/docs/classify/space-settings/#what-is-in-a-classification-level)
(name, colour, description, view and edit groups, label, page header style and
image).

When a template is applied to a space, the levels are **copied into that space**
and the space becomes **linked** to the template. A space is linked to **exactly
one template at a time**: applying a different template moves the link across.

Linked spaces are **template-managed**. When you re-apply a template — for
example after editing one of its levels — the linked spaces you select receive
the updated levels. To make a space independent again, the space admin uses
**Unlink** in Space Settings.

## The template library

The screen lists all global templates. Classify ships with **6 predefined
templates** (for example *Enterprise Standard* and *Simple Business*) that are
seeded automatically the first time you open the screen. You can use these as
they are, edit them, or add your own.

At the bottom of the list you will also find **Documentation** and **Support**
links, which open this guide and the Zeitdocs support portal.

### Creating or editing a template

1. Add a new template or open an existing one.
2. Give it a **name** and **description**.
3. Add **classification levels** — the same fields as space levels.
4. Save.

### Enabling or disabling a template

Each template has an **enabled** toggle. Only **enabled** templates appear to
space admins in the byline onboarding and the "Add from template" picker. Disable
a template to retire it without deleting it.

## Applying a template to spaces

From a template, open **Apply to Spaces** to roll it out. The screen guides you
through four steps: **select → confirm → progress → result**.

Rollouts run **in the background**, so a template can be applied to hundreds of
spaces in a single action.

[Screenshot needed: The Apply to Spaces selection step, showing the search box, the select-all buttons, the selected count, and a space row carrying the "Already linked" badge.]

### 1. Select the spaces

The space list is searchable and paginated at **25 spaces per page**. A selection
can span several pages, so the **selected count** is shown above the list and
always reflects your whole selection, not just the current page.

Four buttons help with large selections:

| Button | Selects |
|---|---|
| **Select page** | Every space on the current page. |
| **Select all matching** | Every space matching your current search. |
| **Select all spaces** | Every space in the site. |
| **Clear** | Nothing — empties the selection. |

Spaces that already use this template carry an **"Already linked"** badge. This
is information only: the row stays selectable, and selecting it means the space
will be **updated** with the template's current levels.

:::note[Very large sites]
On sites with a very large number of spaces, Classify may not be able to list
every space in one request. When that happens, a warning appears above the list
telling you that the list is incomplete. Use the search box to narrow down to the
spaces you need, and note that **Select all spaces** can only select the spaces
that were listed.
:::

### 2. Confirm what will happen

Before anything is written, Classify shows a summary of your selection, grouped
by what will happen to each space:

| Group | Meaning |
|---|---|
| **Will be configured** | The space has no classification configuration yet, or one with no levels. The template will be applied. |
| **Already use this template — will be updated** | The space is linked to this template and will receive its current levels. |
| **Use another template — not changed** | The space is configured from a different template and is left untouched, unless you choose to replace it. |
| **Blocked by Space Access Control** | The space is blocked by policy and is **never** written. |

A **Replace existing templates in selected spaces** checkbox sits below the
summary. It is **unchecked by default**. Ticking it moves the *Use another
template* spaces into the group that will be written, and the summary updates
immediately, so you can see the effect before you commit.

:::caution[Re-applying overwrites local changes]
A linked space is managed by its template. When a space is configured or updated
by a rollout, any classification levels a space admin edited locally in that
space are **replaced** by the template's levels. The confirmation summary tells
you how many spaces this affects before you start.

Space admins are warned about this in Space Settings whenever their levels come
from a template.
:::

:::note[Blocked spaces are always protected]
**Replace existing templates** never overrides Space Access Control. A blocked
space is skipped whatever you select or tick. See
[Space Access Control](/docs/classify/space-access-control/).

A space whose configuration cannot be identified as coming from a known template
— for example one set up before templates were introduced — is treated as *Use
another template*, so it is protected rather than silently overwritten.
:::

### 3. Progress

Once the rollout starts, a progress bar shows how many of the selected spaces
have been processed.

The work runs **in the background on Atlassian's servers**, not in your browser.
You can close the panel, navigate away, or close the browser entirely, and the
rollout continues. If you reopen **Apply to Spaces** for the same template while
a rollout is still running, the progress screen reappears automatically.

[Screenshot needed: The rollout progress screen, showing the progress bar and the message that the rollout continues in the background.]

### 4. Result

When the rollout finishes, you get the outcome for every space in the selection:

- **Configured or updated** — the spaces that received the template.
- **Use another template** — the spaces left untouched.
- **Blocked by Space Access Control** — the spaces skipped by policy.
- **Spaces that failed** — listed individually with the space key, its name, and the reason.

[Screenshot needed: The rollout result screen, showing the outcome summary table and the list of failed spaces with their reasons.]

#### Retrying failed spaces

If any spaces failed, a **retry** action re-runs the rollout for **those spaces
only**. A retry:

- keeps the **Replace existing templates** choice made for the original rollout,
  so it can never widen what gets overwritten;
- re-checks each space against its **current** state, so a space that has since
  been reconfigured, blocked or deleted is handled correctly;
- is itself retryable, up to a small fixed number of attempts.

Some failures are reported as permanent — for example, the template was deleted
while the rollout was running. In that case Classify tells you that retrying will
not help, so you can fix the cause first.

## Seeing which spaces use a template

Each template shows its **linked spaces** as pills (up to 5). If more than five
spaces are linked, a **"+N more"** link opens a dialog listing them all.

Because a space is linked to exactly one template, applying a new template to a
space also removes it from the linked-spaces list of the template it used before.

## Manage access

A **Manage access** button at the bottom of the templates list opens **Space
Access Control**, where you decide which spaces are allowed to use classification
at all. See [Space Access Control](/docs/classify/space-access-control/).

## Tips

- **Edit the predefined templates** rather than starting from scratch — they cover common classification schemes.
- **Disable instead of delete** when retiring a scheme, so existing spaces keep working.
- To push a template change out, edit the template and then **re-apply it to the spaces that use it** — select them in Apply to Spaces and confirm.
- **Read the confirmation summary** before starting a large rollout. It is the point at which you can still see how many spaces will be overwritten.
- Roll out to a **small group of spaces first** when trying out a new template, then repeat for the rest.
